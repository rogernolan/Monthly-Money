# Wheel Of Money Design

## Goal
Add a new `WoM` tab for year-based annual obligations that sit alongside Month and Daily, with their own model, totals, editor, filters, and optional idempotent auto-generated monthly savings entries.

## Product Shape
WoM is separate from Month view.

Month view remains day-based and month-specific:
- `PlannedItem`
- due day / due text
- credits and debits
- month-by-month budgeting

WoM is year-based and annual-obligation specific:
- title
- amount
- month
- paid
- notes
- all entries are debits
- one annual list rather than per-month screens

That difference is large enough that WoM should not reuse `PlannedItem`.

## Data Model
Add a new persisted model: `WheelOfMoneyItem`.

Fields:
- `id: UUID`
- `budgetID: UUID`
- `title: String`
- `amount: Decimal`
- `month: Int` (`1...12`)
- `isPaid: Bool`
- `notes: String`
- `isAutoGeneratedSavingsEntry: Bool`

Add a new budget setting:
- `autoGenerateWoMSavingsEveryMonth: Bool`

This setting is stored on `Budget`, so it follows the same sync/share behavior as the other budget settings.

## UI
### Tab
Add a fourth main tab:
- `WoM`

### Top Chips
Show four chips:
- `Annual total`
- `Monthly average`
- `Pending total`
- `Remaining average`

Definitions:
- `Annual total` = sum of all WoM item amounts
- `Monthly average` = `annual total / 12`
- `Pending total` = sum of unpaid items
- `Remaining average` = `pending total / remaining months in the year`

Colour rule:
- `Remaining average` is red when greater than `Monthly average`
- otherwise use the neutral/plain style

### Filters
Segmented filter:
- `All`
- `Pending`

`Pending` means `isPaid == false`.

### List Rows
Each row shows:
- title
- amount
- month name
- paid checkbox
- disclosure chevron

No credit/debit icon.
No red/green arrow.

### Editor
Editor can change:
- title
- amount
- month
- notes

Editor cannot change:
- paid

Paid remains a list-row action only.

### Delete
Swipe-to-delete with confirmation, matching the rest of the app’s destructive pattern.

## Seed Data
Initial WoM seeds:
- `Car insurance`, `March`, `900`
- `Christmas`, `December`, `1000`
- `J Birthday`, `May`, `150`

## Auto-Generated Savings
If `autoGenerateWoMSavingsEveryMonth` is enabled, the app creates generated WoM entries if missing.

Generation rule:
- one auto-generated WoM entry per month
- title: `WoM savings`
- amount: current `Monthly average` at the time generation happens
- `isAutoGeneratedSavingsEntry = true`

Idempotence rule:
- turning the setting on repeatedly must not create duplicates
- turning it off does not delete generated items
- turning it back on should only create any missing generated entries

Non-goal:
- existing generated entries do not get updated when the monthly average changes later

## Architecture
Keep WoM isolated from Month.

Implementation should mirror the existing app shape:
- new model in app + core package model files
- repository methods for fetch/create/update/delete/toggle paid
- app-state derived totals + filters
- dedicated `WoMView`
- dedicated `WoMItemEditorView` / draft

This keeps Month logic stable and makes WoM easy to reason about.

## Sync And Sharing
WoM data is budget-owned.

That means:
- WoM items sync across the same Apple ID
- shared budgets carry WoM items too
- the auto-generate setting syncs and shares because it is stored on `Budget`

## Testing
Add tests for:
- WoM totals and filter rules
- seed data bootstrap
- idempotent auto-generation
- delete and paid toggle behavior
- remaining-average warning rule
- persistence of the budget setting

## Risks
Main risk:
- adding a new persisted entity to the Core Data / CloudKit-backed graph

This is manageable because WoM items are budget-owned and do not need special sharing behavior beyond normal budget ownership.
